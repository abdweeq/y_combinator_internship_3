# Третья задача: анализ Shiptivitas

## Что сдавать

**task3_submission.html** — один самостоятельный отчёт на английском для Forage.
В нём находятся графики, полный SQL, результаты и три идеи в формате
Hypothesis / Expected impact / Feature. HTML указан среди допустимых форматов
в показанной форме Forage. Отчёт открывается двойным щелчком в браузере.

**answer.sql** — SQL для репозитория. Первый запрос строит DAU по дням и средние
до/после релиза; второй считает реальные смены статуса каждой карточки.
Дополнительные запросы сравнивают равные периоды и проверяют основания для идей.

## Простыми словами

- DAU — сколько разных пользователей вошло за день. Если один человек вошёл
  пять раз, он всё равно считается один раз.
- Kanban выпустили 2 июня 2018 года. За 28 дней до релиза средний DAU равен 5,79;
  за 28 дней после — 12,25. Наблюдаемый рост составляет около 111,7%.
- Это сравнение до/после, а не доказательство, что весь рост вызвала новая
  функция. За эти периоды в продукт входило 24 и 71 разных пользователя.
- В истории 486 записей: 200 созданий карточек и 286 смен статуса. Создание
  карточки не считаем сменой статуса.
- Из 200 карточек 38 ни разу не меняли статус. Из них 35 находятся в backlog
  и к концу данных были созданы как минимум 14 дней назад. Это повод проверить
  гипотезу о напоминаниях, но не доказательство, что эти карточки забыты.
- В базе почти год данных: 3 февраля 2018 — 1 февраля 2019. Не называем её
  недельной выборкой, хотя в истории задания говорится об одной неделе.

## Как повторить расчёты на твоём компьютере

1. Сделай fork https://github.com/insidesherpa/-shiptivitas-3 с названием
   **y_combinator_internship_3** и склонируй его в отдельную папку, например
   **internship #3**.
2. Распакуй файлы архива непосредственно в корень проекта: **answer.sql** и
   **analyze.cjs** должны лежать рядом с исходным **shiptivity.db**.
3. В терминале cmd этого проекта выполни команду **node analyze.cjs**.
   Используется встроенный SQLite из уже установленного Node.js 24.
   Отдельный сервер для этого анализа не требуется.
4. В терминале появятся две небольшие таблицы с основными результатами.
   Полные результаты всех запросов будут сохранены в **analysis-results.json**.
5. Открой **task3_submission.html** в браузере и прочитай выводы и три идеи перед
   загрузкой в Forage.

Исходная база открывается только для чтения. Скрипт не изменяет её данные.
Чтобы заново построить графики и HTML из результатов, можно использовать
**build_report.py** в среде с Python 3 и Matplotlib. Для обычного запуска SQL
и просмотра готового отчёта этот шаг не нужен.

## Файлы проекта

| Файл | Назначение |
| --- | --- |
| answer.sql | Два основных и четыре дополнительных SQL-запроса |
| analyze.cjs | Выполнение SQL через Node.js 24 |
| analysis-results.json | Полные результаты SQL и контрольная сумма базы |
| task3_submission.html | Готовый отчёт с графиками, SQL и тремя идеями |
| build_report.py | Исходный код построения графиков и отчёта |

В архив не включена база: она уже находится в исходном репозитории.
Все даты анализа вычисляются в UTC. Ожидаемое влияние новых идей сформулировано
как гипотезы для проверки; выдуманных результатов экспериментов в отчёте нет.
